# SciType 数据边界与用户自定义方向

## 当前原则

SciType 负责把用户选择的快捷命令转换为符号，但不规定用户必须使用哪一种
缩写，也不根据某个专业中的含义为符号建立不可更改的固定命令。

V0.3a 明确分开以下三层。

### 1. 符号目录

包内 `src/scitype/data/symbols.json` 是与 trigger 无关的符号目录。每条
记录包含：

- 稳定的 `id`；
- 面向用户的符号名称；
- 分类；
- 输出字符或单光标模板。

例如 `γ`、`Γ`、`σ`、`φ` 和 `∫${cursor}dx` 都是独立目录内容。
目录记录不包含用户缩写，也不把符号限定为数学、机械、统计或其他学科中的
某一个含义。

### 2. 用户快捷绑定

快捷绑定与符号目录分离。同一个输出可以被不同用户用不同缩写绑定，也可以
拥有多个别名。

V0.5b 首先实现最小的直接 `trigger → replacement` 底层。用户配置保存在：

```text
%LOCALAPPDATA%\SciType\user_bindings.json
```

用户文件不得与 Python 包内资源混放，也不得在 SciType 升级时被覆盖。
用户文件是带 `schema_version` 的 UTF-8 JSON 对象；`bindings` 数组中的
每项包含 `trigger`、`replacement` 和 `enabled`。这使未来界面能够稳定
新增、编辑、删除和停用单项，并为格式迁移提供明确版本边界。

程序启动时先严格加载包内默认绑定，再加载可选用户文件。启用的同名用户项
覆盖默认绑定；停用的同名用户项从有效集合中移除该 trigger，不会悄悄恢复
默认值。缺少用户文件是合法情况。用户文件损坏时原文件保持不变，运行时
暴露失败状态并安全使用默认绑定；只有默认词库本身损坏才阻止 Hook 安装。

有效集合和用户文档以不可变快照传递。显式 reload 成功会返回新快照，失败
则保留旧快照；当前 Hook 尚未接入运行时快照交换，因此保存后明确要求重启。
V0.5b 不实现文件监听、后台轮询、`trigger → symbol_id` 用户格式或界面。

### 3. 官方预设与当前兼容示例

`src/scitype/data/default_bindings.json` 目前只提供开箱验证和向旧版本兼容
所需的默认示例。它不是唯一缩写标准。`/xw → φ` 因兼容性暂时保留，同时
提供按字母名称组织的 `/fi → φ`。

未来可以提供可选预设，但预设应允许用户导入、修改或删除，不能成为解析器
核心规则。

## 未来自定义界面

后续自定义界面的核心功能计划包括：

1. 搜索或选择符号；
2. 填写用户自己的缩写；
3. 预览最终输出和光标位置；
4. 检测 trigger 冲突；
5. 新增、修改和删除绑定；
6. 导入及导出用户配置。

V0.5b 只完成配置文件、校验、冲突判断、合并、原子保存、显式 reload 接口
及 Windows 启动接入，不实现上述自定义界面、完整预设管理、导入导出或
自动热重载，也不增加化学式、化学反应及化学专用结构。
